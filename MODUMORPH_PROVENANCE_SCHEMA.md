# Evaluation provenance

`request.json` binds checkpoint/config/Strict-OOD97 identity/contract/walker-list SHA256, backend source hashes, complete training XML hashes, evaluation metadata hashes, roots, mode and optional smoke walker. `config.json` is the complete frozen evaluation binding, including source hash map, environment config hash, seeds, scientific overrides and native metric descriptions. Both are required for resume.

`provenance.json` records checkpoint absolute path/filename/hash, original resolved training config path/hash, ModuMorph and MorphAdapt Git SHA + dirty boolean, exact architecture class and parameter count, model max limbs, config RNG seed and independently certified training seed/steps. The native two-element checkpoint contains no certified seed or env-step counter: training_seed and training_steps are **UNKNOWN**; config_seed is reported separately and is not proof of training provenance. No optimizer is constructed. Parameter count includes actor/critic/log_std as in the serialized ActorCritic.

`manifest.json` records Strict-OOD97 source, 97 walker IDs, family, current absolute XML path, frozen XML hash, XML cluster identity/size, current metadata path/hash, split status and TRAIN_TEST_OVERLAP. Identity TSV requires columns walker_id, family, walker_xml, walker_xml_sha256, xml_cluster_id, xml_cluster_size. Old source XML paths are retained in the supplied TSV; runtime paths are rebound only after hash equality. A complete ModuMorph train XML inventory matching resolved config ENV.WALKERS is required; name-only or empty-inventory checks cannot certify zero overlap.

`observation_bindings.json` records real nominal native-vs-bound equality, context hash, valid actuator slots and actual actuator joint order per evaluated morphology. Backend worker receives only normalized proprioceptive, obs_padding_mask, act_padding_mask, edges and immutable context. Native nominal model/data snapshots are used only for preflight comparison. No mutation draw, current mutated mass/gear, history or previous-action field is transported.

Each protocol-setting attempt retains native raw results and traces. Its COMPLETE.json hashes all result/trace files; final COMPLETE.json hashes run files including nested cell certificates. Formal smoke approval checks final hashes and identical request bindings. status.txt is PREFLIGHT_PASS/PREFLIGHT_FAILED, RUNNING, COMPLETE or FAILED. Failure traceback and worker/launcher stdout/stderr remain under logs, and the server shell creates OUTPUT_ZIP for success/failure. Null scientific recovery fields remain null, while non-finite numerical outputs are rejected.

Runtime provenance also records hostname, Python/PyTorch/NumPy/gym/mujoco_py versions, logical device and CUDA_VISIBLE_DEVICES. Real checkpoint/XML/GPU provenance has not been generated locally. The synthetic checkpoint used in unit checks is test-only and is removed; it is never a baseline checkpoint or scientific evidence.

Code/source text, checked-in environment YAML and frozen name-list binding hashes normalize CRLF to LF to match Windows/Linux Git text checkouts. This normalization is explicit in config.json (source_hash_encoding). Checkpoint, supplied training config, real XML/metadata, identity TSV and COMPLETE evidence hashes always use original bytes.
